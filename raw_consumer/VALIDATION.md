# 배치 컬렉션 라우팅 검증 — 2026-11-06

## 추가 설치 재현 검사 — 2026-11-09

`mongo/tests/test_bootstrap.py`로 기존 서비스와 분리한 Compose 프로젝트·빈 볼륨에서
아래 항목을 확인했다. 이 검사는 Kafka 메시지나 기존 DB를 사용하지 않는다.

- 공식 MongoDB 이미지의 빈 볼륨 최초 실행: root·writer·reader 자동 생성,
  `raw_events` 및 라우팅 컬렉션 9개와 인덱스 생성.
- 컨테이너 내부 `verify.js`와 PC의 로컬 공개 포트에서 writer·reader 인증·조회 성공.
- reader 쓰기 거부, 재시작 후 조회 성공. 적재기는 기존 writer로 저장.
- `setup.js`, `setup-writer.js`, `setup-reader.js` 반복 실행 시 기존 계정 정보와 문서 보존.
- 잘못된 관리자/기존 계정 비밀번호·권한에서는 설정 명령이 실패하고 기존 계정 보존.
- 재시작 후 기존 문서·계정 유지, 별도의 새 writer 추가와 재실행 성공.
- 누락·placeholder·중복 계정명은 DB 시작 전에 거부.
- 실제 선택적 QA Compose 구성에서 두 DB의 호스트 해석·조회 인증 성공,
  source가 있는 테스트 원본 조회 성공. 기존 QA 네트워크 유지 및 QA DB 격리 확인.

따라서 아래 2026-11-06 기록의 빈 볼륨 최초 실행 미검증 항목은 이번 검사로
보완했다. Kafka 통합·대량 부하·실제 AWS 배포와 TLS/SASL 검증을 추가한 것은 아니다.

## 확인 완료

- Docker 이미지 빌드, Compose config 검사 통과.
- tests/test_routing.py의 14개 테스트 통과: v1/v2 전체 명시 매핑,
  미분류 사유, Binary/null/headers/고유 키, 건수·시간·바이트 배치 기준,
  다중 파티션 offset, 부분 쓰기 실패 시 미커밋, 커밋 오류,
  소유권 상실/revoke/lost, 정상 종료/종료 기한, 만료 offset 거부.
- 기존 볼륨에 setup.js 두 번 실행. 9개 컬렉션과 각 컬렉션의
  _id_ / raw_kafka_position_v1 인덱스만 존재하는 것을 확인.
- 독립 3파티션 토픽/그룹으로 실제 9개 컬렉션 라우팅 확인.
  표본 14건: 일반 JSON, 미등록 이벤트, 청크, null, 빈 바이트, 비UTF8, 배열 포함.
- 첫 컬렉션은 실제 저장하고 두 번째에서 영구 오류를 주입.
  그룹의 모든 파티션이 미커밋인 상태를 확인.
- 재가입 후 전체 표본 재수신, 중복 문서 없음, 최초 ingestedAt 유지.
- 실제 main.py 자식 프로세스에서 저트래픽 1건 자동 flush와 SIGTERM 종료 코드 0 확인.
- 신규 Consumer를 공통 토픽에 적용. 실제 collector_events 배치 적재 확인.
  조회 순간 lag는 0~2건으로, 1초 배치 대기 중 데이터가 관측됨.
- 전환 중지 시 raw_events 27,994건. 전환 후 같은 건수 유지.
- 기존 웹/Kafka/세 MongoDB 컨테이너 유지, 공유 서비스 정상 상태 확인.
- 실제 .env의 기존 항목은 유지하고 없는 배치/라우팅 fingerprint 항목만 추가.

독립 테스트 source와 UUID 토픽으로 표본이 분류 컬렉션에 남아 있다.
공통 앱 토픽에 테스트 메시지는 주입하지 않았다. 실제 앱에서 계속 발생하는
collector_limitation이 대부분의 실운영 표본이며 생산자 측 변경은 하지 않았다.

## 미검증 및 제한

- 신규 빈 MongoDB 볼륨의 init.js 전체 부팅은 이번 변경에서 실험하지 않았다.
  기존 볼륨 setup 경로는 실제 검증했다.
- 실제 다중 Consumer rebalance/네트워크 단절은 이번 실험에 포함하지 않았다.
  revoke/lost 및 커밋 오류는 단위 테스트로 확인했다.
- 실제 DB 중지 복구 스크립트는 배치 경로로 갱신했지만 이번 변경에서 재실행하지 않았다.
  대신 실제 부분 저장 후 실패·재수신은 통합 테스트로 확인했다.
- 대량 부하, 실제 4 MiB 초과 Kafka 메시지, 문서 한도 초과,
  AWS 배포 및 SASL/TLS는 미검증.
- 원본 컬렉션 간 전역 중복 제거/이동은 없다. 과거 raw_events의 offset을
  강제로 replay하면 새 컬렉션에도 기록될 수 있으므로 그룹 reset을 금지한다.
- raw-routing-v1 규칙은 불변이다. 위치 경계 기반 새 버전 선택 기능은 아직 없으며,
  단순 fingerprint 변경으로 규칙을 교체해서는 안 된다.
