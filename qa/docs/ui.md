# QA 대시보드 UI

화면을 만들거나 고칠 때 보는 문서예요. 규칙 전체는 [`../AGENTS.md`](../AGENTS.md).

---

## 1. UI 기준

- 모든 화면은 **직관성 · 학습성 · 유효성 · 유연성**을 지켜야 해요. 일반적인 관리자 템플릿 모양은 쓰지 않아요.
- **QA와 DB 영역을 나눠서** 보여 줘요. 색으로도 구분해요: **파랑 = QA, 주황 = DB**.
- 테마는 **예매 앱 화면과 같게** 맞춰요.

| 기준 | 화면에서 확인하는 것 |
|---|---|
| 직관성 | 처음 본 사람이 다음에 누를 버튼을 바로 찾는다 |
| 학습성 | 화면마다 같은 자리에 같은 기능 · 단계 표시 |
| 유효성 | 잘못된 입력 · 동시 실행 · 연결 끊김을 화면이 먼저 막거나 알려 준다 |
| 유연성 | 같은 결과에 여러 입구(탭 · 카드 · 결과 버튼)로 들어갈 수 있다 |

## 3. 화면 명세 (확정)

**공통**: 상단 탭 `홈 · QA 대시보드 · DB 대시보드` · 헤더 오른쪽에 시험 대상과 연결 상태 · 화면 속 숫자는 가짜 대상 기준으로 먼저 채움

**흐름**: `01 홈 → 02 시험 설정 → 03 실행 → (자동 이동) 04 결과 → 05 DB 대시보드`
DB 대시보드 입구: 홈 카드 · 04의 "원인 보기" · 상단 탭. 05의 "QA 사례로 저장" → 다음 02 시험의 사례.

### 01 홈
- 배너 "무엇을 확인할까요?" + 통합 검색(실행 번호 · 세션 · 컬렉션)
- 지금 상태: 마지막 실행 · 합격 기준 n / 7 · 정답과 다른 판정 수
- 큰 카드 2개: **시험하기**(파랑 → 02) · **확인하기**(주황 → 05), 카드 안에 다음 단계 순서 표시
- 처음이라면 3단계 안내 · 이어서 하기 3개

### 02 QA 대시보드 · 시험 설정
- 단계 표시: `시험 설정 → 실행 → 결과`
- 시험 대상(가짜 / EC2) · 시험 묶음(여러 개) · 가상 사용자 수(50 · 200 · 500 · 직접) · 시험 시간(120 · 300 · 600초)
- 트래픽 구성(사람 · 봇 A ~ D 비율, 정답표 자동 생성) · 오픈 몰림 · 결과 알림
- 합격 기준은 읽기 전용(기획서 21쪽, 변경은 관리자 승인)
- 오른쪽 실행 요약 + **시험 시작** · 다른 시험이 실행 중이면 시작 잠금 + 남은 시간

### 03 QA 대시보드 · 실행
- 진행한 시간 `n / 300초` 큰 숫자 · 예상 남은 시간 · 진행 막대 · 연결 상태 · **시험 중지**
- 실시간 수치: 판정 API p95 · 오류율 · 초당 이벤트 · Gold 반영 p95 (기준 넘으면 경고)
- 예외 카드: 연결 끊김(다시 연결) · 복구 시험 중 · 시간 초과(설정으로 돌아가기)
- 끝나면 04로 자동 이동

### 04 QA 대시보드 · 결과
- 통과한 합격 기준 `n / 7` · 최종 결과(실패 n건) · 합격 기준 카드 7개 · 보고서 HTML / JSON
- 실패 카드: **DB 대시보드에서 원인 보기** · 설정 바꿔 다시 실행
- 정답과 다른 판정(놓친 봇 · 사람 오탐) → 05 세션 추적
- 지난 같은 조건 실행과 비교 · 정답표 저장 · 알림 · 다음 할 일

### 05 DB 대시보드
- 읽기 전용 표시 · 실행 번호 기준 선택
- 위: Bronze · 격리 · Silver · Gold 판정 · 좌석 점유(Redis 결정 후) · 대기열 · 컬렉션 원본 보기
- 왼쪽: 정답과 다른 세션 목록(전체 · 놓친 봇 · 오탐)
- 오른쪽: 세션 검색(세션 키 · eventId) · 결론 배너 · **QA 정답 VS 시스템 판정** · 예매 단계별 흐름(공연 상세 → 접속 대기 → 보안 확인 → 좌석 선택 → 확정) · 이 세션의 DB 기록 · 클릭 간격 vs 사람 평균 · **QA 사례로 저장**
- 정답 쪽 값은 QA DB에서, 판정 쪽 값은 시스템 DB(읽기 전용)에서 가져와요. 두 값을 시스템 쪽에 다시 쓰지 않아요.

### 매크로 봇 (QA 대시보드 하위 탭)
하위 탭: `시험 실행 · 매크로 봇 · 사례 · 정답표` · 모든 봇 화면에 "우리 앱(웹 · API)에만 접속" 표시

- **B1 봇 목록**: 카드 6개(가상 사람 · A · B · C · D · 새 유형) · 도구 · 용도 · 행동 3줄 · 탐지율과 목표선 · 미달이면 빨간 테두리 + 놓친 세션 DB 보기 · 새 유형은 평가 전용 · 잠김
- **B2 봇 설정**: 프리셋(오픈 즉시형 · 사람 흉내형 · 직접) · ① 진입 시점 ② 클릭 간격 분포(사람과 겹쳐 보기) ③ 화면 흐름 ④ 기기당 세션 수 ⑤ 좌석 없을 때 · 오른쪽에 R1 ~ R6 예상 결과 · 예상 점수 · 가짜 대상 1세션 돌려보기 · 버전 저장 · 바뀐 기록
- **B3 봇 라이브**: 오픈 직후 진입 분포(봇 vs 사람) · 종류별 진행(진입 · 좌석 선택 · 확정 · 판정 받음) · 봇 C 화면 캡처 · 봇 행동 기록
- **B4 탐지 결과**: 종류별 탐지율과 목표선(A · B · D 합계 90% · C 70% · 사람 오탐 1% · 새 유형은 목표 없음) · 정답 × 판정 표(초록 잡음 · 주황 놓침 · 빨강 오탐) · 어떤 규칙이 잡았나 · 놓친 세션 → 05 · 봇 설정 보기 → B2

**연결 (확정 대기)**: 02 "봇 편집" → B1 · 03 "봇 보기" → B3 · 04 "봇별 보기" → B4 · B2 저장 → 다음 02 시험에 반영

## 4. 주소

| 화면 | 주소 |
|---|---|
| 01 · 02 · 03 · 04 | `/` · `/runs/new` · `/runs/{run_id}/live` · `/runs/{run_id}` |
| 05 | `/db?run_id=` · `/db/sessions/{session_key}` |
| B1 · B2 · B3 · B4 | `/bots` · `/bots/{bot_id}/edit` · `/runs/{run_id}/bots/live` · `/runs/{run_id}/bots` |

`session_key`는 세션 구분 키 결정(AGENTS.md 11장) 후 이름을 확정해요.
