# QA 대시보드 UI

화면을 만들거나 고칠 때 보는 문서예요. 규칙 전체는 [`../AGENTS.md`](../AGENTS.md).

---

## 1. UI 기준

- 모든 화면은 **직관성 · 학습성 · 유효성 · 유연성**을 지켜야 해요. 일반적인 관리자 템플릿 모양은 쓰지 않아요.
- **QA와 DB 영역을 나눠서** 보여 줘요. 색으로도 구분해요: **파랑 = QA, 주황 = DB**.
- 테마는 **예매 앱 화면과 같게** 맞춰요.

| 기준 | 화면에서 확인하는 것 |
|---|---|
| 직관성 | 처음 본 사람이 다음에 누를 버튼을 바로 찾는다 |
| 학습성 | 화면마다 같은 자리에 같은 기능 · 단계 표시 |
| 유효성 | 잘못된 입력 · 동시 실행 · 연결 끊김을 화면이 먼저 막거나 알려 준다 |
| 유연성 | 같은 결과에 여러 입구(탭 · 카드 · 결과 버튼)로 들어갈 수 있다 |

## 4. 화면 명세 (확정)

**공통**: 상단 탭 `홈 · QA 대시보드 · DB 대시보드` · 헤더 오른쪽에 테스트 대상(Mock / Live)과 연결 상태 · 화면 속 숫자는 Mock 기준으로 먼저 채움

**흐름**: `01 홈 → 02 Run 설정 → 03 Run 모니터 → (자동 이동) 04 Run 리포트 → 05 DB 대시보드`
DB 대시보드 입구: 홈 카드 · 04의 "DB 원인 분석" · 상단 탭. 05의 "QA 사례로 저장" → 다음 02 Run의 테스트 케이스.

### 01 홈
- 배너 "QA 운영 현황" + 통합 검색(Run ID · 세션 키)
- 현재 상태: 최근 Run · 합격 기준 PASS n / 7 · 오분류 판정 수
- 큰 카드 2개: **테스트 실행**(파랑 → 02) · **데이터 검증**(주황 → 05), 카드 안에 단계 순서 표시
- 온보딩 순서 3단계 · 최근 작업 3개

### 02 Run 설정
- 단계 표시: `Run 설정 → Run 모니터 → Run 리포트`
- 테스트 대상(Mock / Live) · Suite(복수 선택) · 가상 사용자 VU(50 · 200 · 500 · 수동 입력) · 테스트 시간(Mock = 시뮬레이션 시간 표시만) · Suite별 최대 시간(Live · 자동 · 120 · 300 · 600초 · 트래픽 Suite 1개 기준 · 넘은 VU = 시간 초과)
- 트래픽 구성(정상 · 봇 A ~ D 비율, Ground Truth 자동 생성) · 오픈 버스트 · 결과 알림
- 합격 기준은 읽기 전용(기획서 21쪽, 변경 시 관리자 승인 필요)
- 오른쪽 Run 요약 · 예상 소요(Live = 범위 + Suite별 시간 · 실측 · 계산 표시 · 입력 바뀔 때 `POST /runs/estimate`) + **Run 시작** · 다른 Run 실행 중이면 시작 잠금 + 남은 시간

### 03 Run 모니터
- 경과 시간 `n / 예상 소요 초` 큰 숫자(Mock = 시뮬레이션 시간) · 남은 시간(예상) · 진행 막대 · 연결 상태 · **Run 중지**
- 실시간 지표: 판정 API p95 지연 · API 오류율 · 이벤트 처리량(EPS) · Gold 반영 p95 지연 (기준선 초과 시 경고)
- 예외 카드: 대상 연결 끊김(재연결) · 장애 복구 테스트 진행 중 · 예상 시간 초과(Run 재구성)
- 종료 시 04로 자동 이동

### 04 Run 리포트
- PASS 합격 기준 `n / 7` · 최종 판정(FAIL n건) · 합격 기준 카드 7개 · 리포트 HTML / JSON
- FAIL 카드: **DB 원인 분석** · Run 재구성
- 오분류 판정(미탐 FN · 오탐 FP) → 05 세션 추적 · 탐지 리포트 → B4
- 이전 Run 비교(동일 조건) · Ground Truth 저장 · 결과 알림 · 후속 조치

### 05 DB 대시보드
- 읽기 전용 표시 · Run ID 기준 선택
- 위: Bronze · 격리 · Silver · Gold 판정 · 좌석 점유(Redis 결정 후) · 대기열 · 컬렉션 원본 보기
- 왼쪽: 오분류 세션 목록(전체 · 미탐(FN) · 오탐(FP))
- 오른쪽: 세션 검색(세션 키 · eventId) · 결론 배너 · **Ground Truth vs 시스템 판정** · 예매 퍼널(공연 상세 → 접속 대기 → 보안 확인 → 좌석 선택 → 확정) · 이 세션의 DB 기록 · 요청 간격 vs 정상 트래픽 평균 · **QA 사례로 저장**
- Ground Truth는 QA DB에서, 판정은 시스템 DB(읽기 전용)에서 가져옴 · 두 값 모두 시스템 쪽에 다시 쓰지 않음

### 매크로 봇 시뮬레이션 (QA 대시보드 하위 탭)
하위 탭: `테스트 실행 · 매크로 봇 시뮬레이션 · 테스트 케이스 · Ground Truth` · 모든 봇 화면에 "테스트 범위 · 자사 서비스 한정(티켓가드)" 표시

- 봇 이름: 정상 트래픽 · 봇 A · 고속 반복 매크로 · 봇 B · 위장 매크로 · 봇 C · 브라우저 자동화 매크로 · 봇 D · 세션 복제 매크로 · 미학습 유형 봇 (짧은 이름: 정상 · A ~ D · 미학습)
- 이름 · 설명의 원본은 `macro_bots/bot_catalog.py` · 입력 칸은 `macro_bots/behavior_fields.py`

| 번호 | 화면 이름 | 내용 |
|---|---|---|
