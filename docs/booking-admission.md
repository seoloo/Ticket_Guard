# 예매 입장 제한

현재 예매 웹은 사이트 전체를 기준으로 5초 구간마다 최대 40명의 예매 시도를 입장시킨다.
총 수용 인원과 대기열 길이에는 200명 제한을 두지 않는다.

- `BOOKING_ADMISSION_BATCH_SIZE=40`: 한 구간의 최대 입장 수.
- `BOOKING_ADMISSION_INTERVAL_SECONDS=5`: 입장 한도를 갱신하는 간격(초).
- 한도가 남아 있고 앞선 대기자가 없으면 대기 화면 없이 보안문자로 이동한다.
- 한도 소진 시 접수 순서대로 대기하고, 다음 구간에 먼저 등록한 시도부터 입장한다.
- 구간의 첫 입장에서 시간을 계산한다. 비어 있던 구간의 입장 한도는 누적하지 않는다.
- 상태 조회 또는 새 예매 요청 때 대기열을 처리한다. 대기 화면은 1초마다 상태를 조회한다.
- 새로고침이나 동일 요청 재시도는 추가 입장 한도를 소비하지 않는다.
- 취소·만료된 대기자는 제외한다. 입장 후 취소해도 해당 구간에 소비한 한도는 반환하지 않는다.

`.env`에서 값을 변경한 뒤 `docker compose up -d --no-deps web`으로 반영한다.
기존 `QUEUE_WAIT_SECONDS`는 호환용 설정으로 남아 있지만 일반 예매 입장 시간에는 사용하지 않는다.
개발용 `admit` 시나리오는 테스트 목적으로 입장 제한을 우회한다.

## 현재 실행 범위

이 구현은 기존 `MockRepository`와 동일하게 단일 프로세스 메모리와 잠금을 사용한다.
서버 재시작 시 예매 상태, 대기열 및 입장 카운터가 초기화된다.
여러 웹 프로세스 또는 서버를 운영하려면 대기열과 입장 카운터를 공유 저장소로 옮겨야 한다.
Kafka 파티션 설정과는 별개로 예매 시작 단계에서 입장을 제어한다.

## 검사

`docker compose exec -T -e EVENT_PUBLISHER=mock web python manage.py test web`

`web/test_admission.py`에서 동시 요청의 40명 제한, 5초 경계, FIFO 순서,
200명 초과 누적 입장, 중복 요청, 만료된 대기자 제외를 검사한다.
